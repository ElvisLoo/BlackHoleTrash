# 桌面可见性、任务栏与定位手势设计

## 目标

Black Hole Trash 默认作为桌面对象工作：普通窗口没有覆盖黑洞时，黑洞继续显示在露出的桌面区域；普通窗口覆盖黑洞时，黑洞自动隐藏，窗口移开、最小化或关闭后自动恢复。用户可以从托盘开启“始终置顶”来保留当前覆盖所有普通窗口的行为。

无论是否始终置顶，渲染窗口都不得出现在任务栏。原有 `Ctrl+Shift` 跟随定位改为双击 `Ctrl` 后一次性移动并固定到鼠标位置。默认帧率与无效配置回退值从 `60` 改为 `30`，同时继续支持显式选择 `60`。

## 窗口模式

新增布尔状态与配置项 `always_on_top`：

- 缺失或 `always_on_top = 0` 时进入默认桌面模式。
- `always_on_top = 1` 时进入始终置顶模式。
- 托盘增加可勾选的“始终置顶”菜单项，初始勾选状态来自当前运行状态，点击后立即切换，不重建 GPU 设备、交换链或桌面捕获会话。
- 配置文件热重载时同步更新运行状态与托盘勾选。

桌面模式不改变现有全屏、鼠标穿透的渲染结构，而是在 Windows 侧检测黑洞是否被普通窗口覆盖。始终置顶模式跳过遮挡检测，保持现有行为。

## 遮挡检测

Windows 平台新增独立的遮挡检测模块。模块接收黑洞中心、当前事件视界半径和当前外观参数，返回黑洞是否被普通窗口覆盖。

黑洞可见范围与着色器保持一致，使用约为事件视界半径 `7.5` 倍的圆形区域覆盖吸积盘和主要引力透镜效果。窗口矩形与该圆形真正相交时才算遮挡；只碰到圆形外接矩形角落不算遮挡。

枚举 Windows 顶层窗口时忽略：

- Black Hole Trash 自身进程的渲染、托盘和拖放窗口；
- `Progman`、`WorkerW`、主任务栏和副任务栏等系统 Shell 窗口；
- 不可见、已最小化或被 DWM 标记为 cloaked 的窗口；
- 菜单、工具提示等不代表普通应用内容的短暂系统窗口。

其余可见普通窗口使用 DWM 扩展边框计算实际矩形；DWM 单窗口查询失败时回退到 `GetWindowRect`。任一普通窗口与黑洞可见圆相交，就判定为被覆盖。多显示器环境中，只要黑洞任一可见部分被覆盖，就隐藏整个黑洞，避免跨屏对象只剩半边。

检查间隔目标为 `100 ms`。遮挡状态没有变化时不重复调用窗口显示 API。整轮枚举无法可靠完成时采用隐藏策略，避免黑洞意外覆盖用户正在使用的应用。

## 显示状态与交互

最终显示条件由现有屏幕保护条件和新的窗口模式共同决定：

```text
should_show = screensaver_wants_visible
           && (always_on_top || !black_hole_occluded)
           && pane_is_ready
```

从显示切换为隐藏时：

- 隐藏所有渲染 Pane，不执行系统最小化动画；
- 隐藏并禁用 OLE 拖放窗口；
- 禁用鼠标引力场并恢复可能被程序隐藏的系统光标；
- 停止提交渲染帧，保留现有低功耗等待路径。

从隐藏恢复时，先在隐藏状态预绘一帧，再显示 Pane，并继续执行现有捕获排除校验。文件拖放入口和鼠标引力只在黑洞实际可见时启用，不能在被应用遮挡时拦截鼠标或文件拖放。

## 任务栏排除

Windows 渲染窗口在创建时显式启用 winit 的任务栏排除选项，并验证原生扩展样式：保留 `WS_EX_TOOLWINDOW`，移除会强制显示任务栏按钮的 `WS_EX_APPWINDOW`。窗口重新显示、切换始终置顶或重建多显示器 Pane 后，任务栏排除属性必须保持不变。

现有拖放窗口已经使用 `WS_EX_TOOLWINDOW`，继续保持。若渲染窗口无法可靠应用或验证任务栏排除属性，采用失败关闭策略，不显示违规的主窗口。

## 双击 Ctrl 定位

删除持续轮询 `Ctrl+Shift` 的旧定位条件。Windows 平台新增双击 Ctrl 状态机：

- 第一次独立按下并释放 `Ctrl` 后开始计时；
- 在 `350 ms` 内第二次独立按下 `Ctrl` 时触发一次；
- 长按不重复触发；
- 两次点击之间出现其他按键，或同时按下 `Shift`、`Alt`、`Win` 时取消候选；
- 触发后读取全局鼠标坐标，把黑洞中心移动到该位置并设为固定位置；
- 不恢复旧的 `Ctrl+Shift` 行为，直接用鼠标拖动黑洞仍然有效。

键盘监听失效时记录错误并保留直接拖动和托盘位置选项，不使用可能误触的单次 Ctrl 作为降级行为。

## 默认帧率

`DEFAULT_FPS` 改为 `30`。帧率仍只有 `30` 和 `60` 两档：

- 配置缺失时使用 `30`；
- `fps = 30` 使用 `30`；
- `fps = 60` 使用 `60`；
- `fps = 0`、负数、无法解析或其他数值统一回退到 `30`；
- 托盘启动时默认勾选“30 帧”；
- 默认配置模板、README 和中英文说明同步更新。

## 错误处理与兼容性

- Windows 10 2004、Windows 11 和多显示器是本功能的支持范围。
- 遮挡检测只在 Windows 启用；macOS 保持当前窗口行为，并继续通过条件编译检查。
- Explorer 或 DWM 的单个窗口信息变化不能导致进程退出；该窗口使用回退矩形或在本轮保守判定为遮挡。
- 始终置顶切换只改变遮挡策略，不放宽捕获排除验证，不改变安全回收规则。
- 屏幕保护模式、截图修复、外观、成长、拖放回收与配置热重载继续工作。

## 验证

自动化测试覆盖：

- 圆与窗口矩形相交、不相交、相切和矩形角落误判；
- 自身、Shell、隐藏、最小化和 cloaked 窗口的过滤决策；
- `always_on_top` 缺失、关闭、开启和非法值的解析与默认值；
- 双击 Ctrl 正常触发、超时、长按、夹杂其他键和修饰键组合；
- 默认、缺失和非法 FPS 均归一化为 `30`，显式 `60` 保持为 `60`；
- 托盘选项与配置热重载状态同步。

Windows 运行验证覆盖：

- 启动后任务栏没有 Black Hole Trash 按钮，托盘图标存在；
- 普通窗口未覆盖黑洞时黑洞保持显示；覆盖时隐藏，移开、最小化和关闭后自动恢复；
- 始终置顶开启后普通窗口不再触发隐藏，关闭后立即恢复遮挡策略；
- 黑洞隐藏时拖放入口和鼠标引力不再生效；
- 双击 Ctrl 将黑洞移动并固定到鼠标位置，`Ctrl+C`、`Ctrl+V` 和长按 Ctrl 不触发；
- 多显示器切换与跨屏位置正常；
- 默认帧率为 `30`，托盘切换到 `60` 后帧调度正常。

最后执行 `cargo fmt --all -- --check`、`cargo test --all-targets`、`cargo check --all-targets` 和 Release 构建。
