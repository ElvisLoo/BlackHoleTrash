# 吞噬喷流与冲击光波设计

## 目标

当 Windows Shell 确认一批文件或文件夹已成功移入回收站后，黑洞播放一次 0.90 秒的能量释放动画。动画包含一束明亮主喷流、一束极淡的反向喷流、中心爆闪，以及从事件视界向外扩散的冲击光波。效果应跟随黑洞的位置、尺寸和吸积盘朝向，并在多显示器上保持连续。

失败、取消或已经过期的回收结果不触发动画。手动切换黑洞尺寸也不触发动画。

## 视觉行为

- 主喷流沿吸积盘投影短轴向屏幕上方一侧射出，外观以白色高亮核心、冷蓝紫色内辉光和轻微丝状扰动组成。
- 反向喷流沿相反方向射出，长度略短，峰值亮度约为主喷流的 18%，用于暗示双极结构但不抢占桌面视觉。
- 中心爆闪在动画开始时快速增强，再迅速退去。
- 冲击光波从黑洞中心向外扩散，形成窄而柔和的蓝白色圆环；圆环在动画后半段消失。
- 喷流方向使用当前外观的 `roll` 参数，与吸积盘画面朝向保持垂直关系，不使用固定屏幕角度或随机方向。

## 动画节奏

完整动画持续 `0.90` 秒：

1. `0.00-0.12` 秒：中心爆闪，喷流快速建立。
2. `0.12-0.45` 秒：主喷流达到峰值，冲击光波向外扩散。
3. `0.45-0.90` 秒：喷流宽度收束、亮度衰减，冲击光波和余辉消失。

同一批次只播放一次。若上一段动画尚未结束时又有一批文件成功回收，新事件从零重新开始，并采用新批次的强度。

## 批次强度

强度按当前成功回收批次中的顶层项目数计算，不递归统计文件夹内容。一个项目使用基准强度；项目数量按对数曲线温和增强，并在 20 个项目时封顶：

```text
energy = 1.0 + 0.5 * ln(clamp(count, 1, 20)) / ln(20)
```

因此能量范围为 `1.0-1.5`。着色器使用该值略微增加喷流亮度、宽度和冲击波最大范围，不增加动画时长，也不按项目数连续播放。

## 架构

采用现有单 Pass WGSL 渲染管线，不新增窗口、纹理或渲染 Pass。

`State` 保存喷流开始时间和批次能量。当前的 `PlatformEvent::RecycleFinished` 成功分支在更新吞噬成长进度后触发喷流；失败分支和过期 generation 分支保持现状。

CPU 每帧计算归一化进度和能量，通过新增的一个 `vec4<f32>` uniform 传给所有 Pane：

```text
x = 0.0-1.0 的动画进度
y = 1.0-1.5 的批次能量
z = 是否激活（0 或 1）
w = 保留，写 0
```

WGSL 新增独立的 `absorption_jet_overlay` 函数。它使用黑洞中心、半径、当前 `roll`、喷流进度和能量计算主喷流、反向喷流、中心爆闪与冲击环，并以受控的加色方式叠加到黑洞最终颜色。该函数在鼠标代理绘制前调用，使鼠标反馈仍保持可见。

## 数据流

```text
有效的 RecycleFinished(success)
  -> 计算顶层项目数对应的 energy
  -> 重置 State 中的喷流开始时间
  -> 每帧把 progress / energy / active 写入各 Pane uniform
  -> WGSL 程序化绘制喷流与冲击光波
  -> 0.90 秒后 active 自动归零
```

## 边界与故障行为

- 空批次不触发效果。
- 项目数量大于 20 时使用 20 对应的最大强度，计算不会溢出。
- 回收失败、Shell 取消、过期 generation 均不触发效果。
- 效果不改变吞噬累计数、尺寸档位、配置文件或托盘菜单。
- shader 只使用数学图元，不依赖外部图片资源；效果结束后只增加固定数量的廉价格像素运算。

## 测试与验证

- Rust 单元测试覆盖批次 `0/1/2/20/usize::MAX` 的能量边界。
- Rust 单元测试覆盖动画在开始、中段、结束和超过 0.90 秒后的 active/progress 状态。
- Rust 单元测试断言成功吞噬可创建新喷流状态，空批次不可创建。
- 离线运行 naga WGSL 解析与校验。
- 运行格式检查、完整单元测试和 `cargo check --all-targets`。
- 运行程序进行桌面视觉检查，确认喷流从黑洞中心发射、方向随吸积盘旋转、跨 Pane 不跳变，动画结束后无残影。
